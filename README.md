# Електронний журнал обліку відвідування навчальних занять

Десктопний застосунок для одного викладача: облік відвідування й оцінок студентів, підсумки та експорт (курсова робота з дисципліни «Інструментальні засоби візуального програмування»). Дані зберігаються локально в SQLite, інтернет не потрібен.

## Можливості

- Групи, студенти й дисципліни: створення, редагування, архівування без видалення даних.
- Заняття: група, дисципліна, дата, номер пари 1–8, тема; дубль «група + дата + пара» відхиляється. Повторюване заняття: одна дія створює заняття на обраний день тижня (щотижня або раз на 2–4 тижні) між двома датами, до одного року; зайняті дати пропускаються.
- Відмітки: Присутній, Відсутній, Запізнився, Поважна причина, оцінка 0–100 і коментар; «Усі присутні»; уся сторінка зберігається однією дією в одній транзакції.
- Редагування збереженої відмітки лише з причиною (щонайменше 5 символів); кожна зміна — нова версія, попередні доступні в історії та можуть бути відновлені.
- Місячна сітка групи з фільтром за дисципліною; статус показано літерою, а не лише кольором; клік відкриває заняття.
- Підсумки за період: відсоток відвідування та середній бал по студентах і по групі.
- Імпорт студентів із CSV/XLSX з попереднім переглядом помилок і дублікатів; експорт відвідуваності в CSV/XLSX.
- Журнал змін з фільтрами за датою, типом об'єкта та дією; записи не редагуються.
- Українська й англійська мови, світла й темна теми без перезапуску.
- Робота лише з клавіатури на екрані відміток.

## Вимоги

- Windows 10 або 11, x64.
- Для збирання: .NET SDK 10 (версія з `AttendanceJournal.csproj`, `net10.0`).
- Для запуску опублікованої версії нічого встановлювати не треба (self-contained), права адміністратора не потрібні.

## Збирання та запуск

```powershell
git clone <url-репозиторію>
cd AttendanceJournal
dotnet build
dotnet run --project AttendanceJournal.csproj
```

База даних створюється автоматично під час першого запуску: `%LOCALAPPDATA%\AttendanceJournal\journal.db`. Журнал помилок: `%LOCALAPPDATA%\AttendanceJournal\logs\errors.log` (без персональних даних).

## Як користуватися

1. **Групи та студенти** — створіть групу (напр. ІПЗ-21, 2026-2027) і додайте студентів вручну або кнопкою «Імпорт студентів…» (файл із `samples/`). Перед імпортом показується перелік рядків з номерами й причинами пропуску.
2. **Дисципліни** — додайте дисципліни.
3. **Журнал занять** — оберіть групу й дату, створіть заняття (або позначте «Повторюване заняття (серія)», щоб створити заняття на весь семестр), відмітьте студентів і натисніть «Зберегти відмітки». Щоб змінити збережену відмітку, змініть її та вкажіть причину. «Історія» показує всі версії відмітки.
4. **Місячна сітка** — огляд місяця; клік на клітинці відкриває заняття.
5. **Підсумки та експорт** — оберіть період, перегляньте відсотки й середні бали, експортуйте в CSV або XLSX.
6. **Журнал змін** — перегляд усіх операцій.

Клавіатура на екрані відміток: Tab — наступне поле, Ctrl+1…4 — статус рядка (П, Н, З, ПП), Ctrl+S — зберегти, Ctrl+M — усі присутні.

### Формат файлу імпорту

Перший рядок — заголовки. Обов'язкова колонка `FullName` (або `ПІБ`), необов'язкова `Group` (або `Група`); регістр не важливий. CSV — у кодуванні UTF-8, роздільник `,` або `;`. Рядки без групи потрапляють у групу, обрану в списку. Групи, яких ще немає, створюються лише після підтвердження.

## Демонстраційні дані

Папка `samples/` містить лише вигадані дані:

- `students.csv`, `students.xlsx` — коректний список із двох груп;
- `students-with-errors.csv` — файл з порожнім ПІБ, дублікатом, занадто довгим ПІБ, рядком без групи та новою групою для демонстрації попереднього перегляду.

## Структура проєкту

| Папка | Призначення |
|---|---|
| `Models/` | Сутності, переліки, обмеження довжини полів |
| `Data/` | `AppDbContext`, конфігурації EF Core, міграції, ініціалізація БД |
| `Services/` | Бізнес-правила: групи, студенти, дисципліни, заняття, відмітки, підсумки, місячна сітка, імпорт, експорт, журнал змін; `Services/Common` — результат операцій, ключі помилок, аудит, журнал збоїв |
| `ViewModels/` | Стан екранів і команди (CommunityToolkit.Mvvm), локалізація (`Localization/`), інтерфейси для діалогів |
| `Views/` | Розмітка Avalonia, діалоги підтвердження та вибору файлів, перемикання теми |
| `tests/AttendanceJournal.Tests/` | Автоматичні тести (xUnit v3) |
| `samples/` | Синтетичні файли для імпорту |

Залежності спрямовані в один бік: Views → ViewModels → Services → Data → Models.

## Відомі обмеження

- Один користувач на одному комп'ютері; входу в систему та синхронізації немає.
- Журнал змін фіксує операції, виконані через застосунок. Зміни, внесені безпосередньо у файл бази даних, він не виявляє (доступ до файлу має лише викладач).
- Однофамільців з однаковим повним ПІБ в одній групі додати не можна; додайте, наприклад, ініціали по батькові.
- Тексти помилок перекладаються в момент появи; після зміни мови вже показане повідомлення лишається попередньою мовою до наступної операції.
- Резервне копіювання бази та графіки не реалізовано.
